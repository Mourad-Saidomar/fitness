7 étapes | Back-end Node.js/Express sur Alwaysdata | MariaDB | Front-end Vue.js

3. Étapes détaillées : Préparation, Installation et Mise en service

01 · Préparer l'application Étape validée
  • Version déployée : Version 1.0.0 — Commit Git fbbc888.
  • Vérification du code source : Point d'entrée src/app.js, pool MariaDB dans src/config/db.js, présence de package.json et package-lock.json.
  • Écoute dynamique : src/app.js utilise bien process.env.PORT || 3000 et process.env.IP || process.env.HOST || "0.0.0.0".
  • Sécurité des secrets : Création de backend/.env.example (sans secrets) et backend/.gitignore excluant node_modules/ et .env.

Résultat attendu : Le projet est complet et ses dépendances, versions et configurations sont connues.

Preuve / contrôle : Fichiers package.json, .env.example et référence Git fbbc888.

☑ Étape validée    ☐ À corriger    Observations : Projet complet et testé en local.
02 · Préparer l'environnement Alwaysdata Étape validée
  • Accès administration : Connexion sur https://admin.alwaysdata.com avec le compte saidomar.
  • Accès distant SSH / SFTP : Hôte ssh-saidomar.alwaysdata.net (Port 22), utilisateur saidomar, connexion SSH activée.
  • Runtime Node.js : Vérifié dans Environnement > Node.js (version LTS compatible Express 5 / bcrypt 6).
  • Emplacement cible : Répertoire /home/saidomar/www/api et adresse publique https://saidomar.alwaysdata.net.

Résultat attendu : L'hébergement est prêt à recevoir l'API Fitness.

Preuve / contrôle : Connexion SSH et SFTP fonctionnelle sur ssh-saidomar.alwaysdata.net.

☑ Étape validée    ☐ À corriger    Observations : Accès SSH et FileZilla opérationnels.
03 · Préparer la base MariaDB Étape validée
  • Base MariaDB créée : saidomar_fitness sur le serveur mysql-saidomar.alwaysdata.net (port 3306).
  • Utilisateur SQL : saidomar avec l'autorisation « Tous les droits » (lecture + écriture) sur saidomar_fitness.
  • Import SQL via phpMyAdmin : Importation du script database.sql dans la base saidomar_fitness (en ciblant directement la base saidomar_fitness sans exécuter DROP/CREATE/USE fitness).
  • Contrôle SQL effectué dans phpMyAdmin : 
    SHOW TABLES;
SELECT a.id_adherent, u.nom, u.prenom, a.poids, a.imc, a.contrat
FROM adherent a JOIN utilisateur u ON a.id_utilisateur = u.id_utilisateur LIMIT 10;

Résultat attendu : La base saidomar_fitness et ses 11 tables (role, droit, role_droit, compte, utilisateur, abonnement, adherent, coach, salle, seance, participation) sont accessibles.

Preuve / contrôle : Liste des tables et affichage des 5 adhérents de test dans phpMyAdmin.

☑ Étape validée    ☐ À corriger    Observations : Import SQL terminé avec succès dans saidomar_fitness.
04 · Installer le back-end Node.js / Express (FileZilla + SSH) Étape validée
  • Transfert SFTP avec FileZilla : Connexion à ssh-saidomar.alwaysdata.net (port 22, user saidomar), création du dossier /home/saidomar/www/api et envoi de src/, package.json et package-lock.json (sans node_modules/ ni .env).
  • Installation des dépendances en SSH : 
    ssh saidomar@ssh-saidomar.alwaysdata.net
cd /home/saidomar/www/api
node -v && npm -v
npm ci --omit=dev

Résultat attendu : Les fichiers et les modules de production (node_modules/) sont installés sur Alwaysdata.

Preuve / contrôle : Exécution de npm ci --omit=dev sans erreur dans le terminal SSH.

☑ Étape validée    ☐ À corriger    Observations : Dépendances installées proprement via SSH.
05 · Configurer et démarrer l'API Étape validée
  • Configuration dans Web > Sites : Site de type Node.js sur l'adresse saidomar.alwaysdata.net.
  • Répertoire de travail : /home/saidomar/www/api
  • Commande de démarrage : node /home/saidomar/www/api/src/app.js (ou npm start).
  • Variables d'environnement configurées sur le site : 
    NODE_ENV=production
DB_HOST=mysql-saidomar.alwaysdata.net
DB_PORT=3306
DB_NAME=saidomar_fitness
DB_USER=saidomar
DB_PASSWORD=[SECRET_MASQUÉ]
JWT_SECRET=[SECRET_MASQUÉ]
JWT_EXPIRES_IN=1h
  • Démarrage : Enregistrement et redémarrage du site dans Web > Sites ; vérification des journaux (Web > Sites > Logs).

Résultat attendu : L'API démarre et répond sur https://saidomar.alwaysdata.net.

Preuve / contrôle : Réponse HTTP 200 OK sur https://saidomar.alwaysdata.net/.

☑ Étape validée    ☐ À corriger    Observations : L'API écoute sur les variables IP/PORT fournies par Alwaysdata.

  • Configuration de l'URL de production : Paramétrage de VITE_API_URL=https://saidomar.alwaysdata.net (aucun appel à localhost en production).

Résultat attendu : Le front-end publié échange correctement en HTTPS avec l'API Alwaysdata.

07 · Tester et valider le déploiement (Postman) Étape validée
  • Test de mise en ligne HTTP : GET https://saidomar.alwaysdata.net/ → Code 200 OK (Hello World!).
  • Tests de lecture MariaDB (routes publiques) :
    • GET https://saidomar.alwaysdata.net/coachs → 200 OK (liste des 4 coachs)
    • GET https://saidomar.alwaysdata.net/seances → 200 OK (liste des 5 séances)
    • GET https://saidomar.alwaysdata.net/abonnements → 200 OK (liste des 4 abonnements)
  • Test d'authentification JWT : POST https://saidomar.alwaysdata.net/auth/login avec {"email":"admin@fitness.com","password":"password123"} → Retourne un accessToken JWT valide.
  • Tests CRUD complets sur les adhérents (avec Header Authorization: Bearer <TOKEN>) :
    • GET https://saidomar.alwaysdata.net/adherents → 200 OK
    • POST https://saidomar.alwaysdata.net/adherents (création d'un adhérent fictif) → 201 Created
    • PUT https://saidomar.alwaysdata.net/adherents/:id (modification du poids) → 200 OK
    • DELETE https://saidomar.alwaysdata.net/adherents/:id (suppression du test) → 200 OK

Résultat attendu : La version déployée est utilisable en ligne et toutes les vérifications Postman sont validées.
